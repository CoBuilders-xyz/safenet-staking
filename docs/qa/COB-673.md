# COB-673 verification

The CLI and MCP now read complete indexed history with a bounded RPC tail.
This report records read-only verification on 2026-11-05.
No package publication, deployment, or live transaction was involved.
QA used public endpoints without operator credentials.

## Baseline and cause

Base: `35e043241881eae686a7f98fa32b2bcbe3efcbe9`, fetched from `origin/main` before edits.
Both package versions remain `0.1.0-beta.1`; this PR is not a release.

Without an RPC override, these baseline commands failed:

```sh
env -u MAINNET_RPC_URL node --import tsx packages/cli/src/index.ts rewards history 0x6fe95669af152f96e3c81bf6ae16e75ef7bb1558 --json
env -u MAINNET_RPC_URL node --import tsx packages/cli/src/index.ts withdrawals list --json
env -u MAINNET_RPC_URL node --conditions=source --import tsx packages/mcp/scripts/client.ts rewards_history '{"address":"0x6fe95669af152f96e3c81bf6ae16e75ef7bb1558"}'
```

| Read | Baseline | Fixed public-endpoint result |
|---|---|---|
| CLI rewards history | Exit 1; Claimed scan refused at blocks 24749707–24750706 | Exit 0; 10 claims; sum matches `cumulativeClaimed` |
| CLI network withdrawals | Exit 1; WithdrawalClaimed scan refused at blocks 24585750–24586749 | Exit 0; 121 initiated, 99 claimed, 22 pending |
| MCP rewards_history | `isError`; the same historical scan failure | Successful structured content, with matching count and total |

PublicNode returned HTTP 403 / JSON-RPC -32602 for historical ranges of 50,000, 1,000, and **one** block:
`Archive requests require a personal token. Get one at: https://www.allnodes.com/publicnode`.
Shrinking below 1,000 blocks therefore could not solve that provider's access restriction.
The second default, LlamaRPC, returned HTTP 525: its upstream TLS handshake failed.
This reproduces today's failure mechanism; it does not establish LlamaRPC's exact state on November 2.

Historical logs do not inherently require archive state.
Providers separately restrict log retention, request size, request rate, and paid access.
The previous advice incorrectly treated every failure as an archive-state requirement.

## Coverage and implementation

The deployed schema and handlers cover these records:

- `RewardClaim`: one immutable event, keyed by transaction hash and numeric log index.
  `amount` is the individual payment, not the cumulative amount.
  `RewardAccount.claimCount` and `cumulativeClaimed` check page completeness and amounts.
- `Withdrawal`: one globally numbered initiation, updated by its claim event.
  Claimed rows remain available. Reading **all** rows preserves initiation and claim counts.
  `Network.withdrawalCount` checks row count; `pendingWithdrawals` checks the open sum.
- `RewardPeriod`: distribution boundaries, with approximate whole-block attribution.
  It cannot attribute claims precisely around a root update within the same block.
  Existing optional period checks remain unchanged and report `periodsReason` when unavailable.

History queries pin every page to one block hash, validated against the RPC block and timestamp.
ID cursors avoid skip limits. Missing fields, GraphQL errors, count mismatches, duplicates,
indexing errors, and inconsistent boundaries reject the indexed result.
Indexes older than 15 minutes behind the captured chain head are explicitly stale.
An index ahead of the captured head is queried at that earlier head.

RPC scans fill every block after the indexed snapshot through the captured head.
History scans can shrink to one block and retry rate-limited requests.
Existing scan callers retain their original minimum.
Contract totals must match the indexed history plus tail.
If this path fails, a complete historical RPC scan is attempted.
If both paths fail, CLI exits 1 and MCP returns `isError`, without partial or false-empty data.

JSON keys, exact wei values, full counts and totals, newest-20 behavior, `--all`, and sorting remain intact.
The existing source fields identify indexed coverage and completed RPC lag.
A complete result refers to its captured `block`, not perpetual freshness.
RPC-only fallback retains the existing mismatch flags and human warnings.
Address-scoped withdrawals, status, validators, rewards check, and write implementations remain unchanged.

## Limits

- PublicNode sometimes returned no historical receipt. dRPC served the affected receipts.
  A later direct retry also found one previously absent receipt on PublicNode; pruning was not established.
- LlamaRPC returned HTTP 525. Lava's old public endpoint returned HTTP 410 and said it was discontinued.
  BlockPI did not produce a usable JSON response in the probe. These were not used as evidence sources.
- The default Studio subgraph is public and rate limited. Its outage can still prevent history when RPC history also fails.
  Such failure is explicit. No source can guarantee availability during simultaneous upstream failures.
- Optional per-period comparisons still need historical contract state. Public RPC refused those reads during QA;
  claims remained complete, while `periods` was null with an explicit reason.
  The existing period reader also explicitly declines a full 1,000-row period query; it never silently truncates.
- CI status and the final PR head are reported with the PR. The artifact embeds the exact source head.
