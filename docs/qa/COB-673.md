# COB-673 verification

Base: `35e043241881eae686a7f98fa32b2bcbe3efcbe9`. Read-only checks on 2026-11-05.
CLI and MCP remain at `0.1.0-beta.1`; this is not a release.

## History failure and fix

Baseline reward history and network withdrawals failed on the default public RPCs.
PublicNode rejected historical logs with HTTP 403, even for one block; LlamaRPC returned HTTP 525.
These are provider restrictions and availability failures, not proof that all historical logs require archive state.
The fix pages indexed records at one verified block hash, fills the recent gap with RPC logs,
and checks exact totals against the contract. Both sources failing produces an explicit error.

CLI/MCP installed from tarballs in a clean external prefix passed history and read-only regressions.
Receipt checks independently verified 34 claims across three addresses and an empty control.
All 121 withdrawal initiations, 99 claims, and 74 staker queues matched.
At block 26350666, 22 withdrawals totaled `5924636414532364462762668` wei.
An independent box also verified the prior CI tarballs at `0122a3c`.

## Why period comparisons were unavailable

The failure was **historical RPC state verification**, not the GraphQL period query.
Both readers use `ctx.subgraphUrl`, the same endpoint resolver, and the same gateway fallback.
Precedence is explicit `SUBGRAPH_URL_MAINNET`, then the `GRAPH_API_KEY` gateway, then the public Studio default.
No separate period endpoint or credential is configured.

Tracing PublicNode explicitly showed:

| Request | Result |
|---|---|
| Subgraph `_meta` | HTTP 200, no GraphQL errors |
| Pinned `RewardPeriod` and `RewardClaim` query | HTTP 200, 17 periods and 14 claims |
| RPC block metadata | Success |
| Historical `eth_call` of `MerkleDrop.cumulativeClaimed(address)` at block 25035386 | HTTP 403, RPC -32602: archive requests require a personal token |
| Same period reader with `https://eth.drpc.org` | 17 periods; every comparison matched |

The period reader was unchanged between base `35e0432` and `0122a3c`.
Its catch-all `periodsFailure()` incorrectly attributed RPC exceptions to the subgraph before this PR.
The fix identifies RPC block reads versus historical contract calls, including the period, block and HTTP status.
Provider bodies and credential-bearing URLs are never included.
Unavailable historical state still produces `periods: null` and a truthful `periodsReason`.
Existing mismatch and stale-index indicators remain intact.

Reproduce the successful GraphQL query without any credential:

```sh
curl -sS https://api.studio.thegraph.com/query/1763864/safenet-mainnet/e66567d \
  -H 'content-type: application/json' \
  --data '{"query":"{ _meta { block { number } } rewardPeriods(first: 1000, orderBy: period) { period blockNumber timestamp } }"}'
```

For the full CLI period comparisons, use a provider that serves historical contract state:

```sh
safenet --rpc-url https://eth.drpc.org rewards history 0xef4a4960af328750b8bdc9fe0df15f39f2d124b1 --json
```

For MCP, start with `SAFENET_MCP_RPC_URL=https://eth.drpc.org`, then call `rewards_history` for that address.
Public endpoint availability can change. No shared RPC default or signing path was changed.
The existing period reader explicitly refuses full 1,000-row queries instead of silently truncating them.
